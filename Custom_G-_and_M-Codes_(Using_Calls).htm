Custom G-Codes and M-Codes (Using Calls)

You can use #define preprocessor directives and the CALL or FARCALL command to replace any G-Code or M-Code with a program. The axis block that normally accompanies that G-Code is interpreted as arguments to the program. Also, you can change the G-Code override on and off by using the #undef and #include preprocessor directives.

The following example programs use defines and inline comments to explain customization. You must understand the #define and #include preprocessor directives, CALL or FARCALL commands, and the syntax of words and call arguments before you continue.

In the first example program, the G1 command is replaced with a call to the subroutine myG1 that changes the G1 command parameters.

The .DEFINED keywords are used to make sure that only the parameters that are passed into the program are processed. You must examine the .DEFINED argument variant before you use the argument value or the data is not defined.

Example

' A normal G1.
N01 G1 X2 Y2                

' Replace G1 with a call to myG1.			
#define G1 CALL myG1\x20
				
' This calls myG1, which redefines the G1 command and is the same as N02, but does not have separating spaces. 
N02 G1 X21 Y20              
N03 G1X21Y20               

' Go back to normal G1.
#undef G1      
' A normal G1.             
N04 G1 X-20 Y-20           
END PROGRAM

DFS myG1
G1 X($X / 1000) Y($Y / 1000)
ENDDFS

At the end of the first #define statement in the \x20, (between N01 and N02), the \x tells the compiler that the next two digits specify the hexadecimal code of an ASCII character to insert. In this case, 20 is the hexadecimal code for a space. Without this trailing space, a compiler error occurs in line N03 because the subroutine name would be seen as myG1X2.1Y2. You must use this procedure because the compiler removes trailing spaces from replacement strings (at the end of the #define statement).

The following example shows that this technique is not limited to spaces. You can insert any ASCII code in this way. This technique is also not exclusively limited to the end of the #define statement.

; This is the same as "#define G1 CALL myG1".
#define G1 CALL /x60/x79/x47/x31

The following example shows you how to use a binary input to enable or disable a G1 command. If the binary input is not enabled, then the G1 line is bypassed and the axis does not move. Because the subroutine uses the G1 to do the motion, the custom G1 #define statement must be disabled before the standard G1 is used.

This example works only in G91 mode, or if both X and Y values are passed in on each move. For example, in G90 mode and at point {3, 3}, an execution of G1 X6 moves to {6, 0}, not the expected {6, 3}. Use the DEFINED keyword to correct this defect.

Example

' Replace G1 with a call to myG1.
#define G1 CALL myG1            
F200							
N01 G1 X10 Y10
N02 G1 X10 Y10 F10             
N03 G1 X10 Y10 p100             
N04 END PROGRAM

DFS myG1
' If it is okay to move.
    IF ($BI[2] == 0)  
' So I can call the normal G1.          
        #undef G1              
        $global[0] = 0
' Feedrate was passed in with p. Use it.
        IF ($p.DEFINED)      
            G1 X$X Y$Y F$p
' Feedrate was passed in with F. Use it.
        ELSEIF($F.DEFINED)       
            G1 X$X Y$Y F$F
' No feedrate was passed in. Use the default.
        ELSE                    
            G1 X$X Y$Y
        ENDIF
' To reestablish myself.
        #define G1 CALL myG1
    ENDIF
    RETURN
ENDDFS
