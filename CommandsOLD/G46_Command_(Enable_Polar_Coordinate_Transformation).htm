G46 Command (Enable Polar Coordinate Transformation)

Syntax: 
G46 <LinearAxis> <RotaryAxis>

Example:

 
G46 U C    ; Define U axis as the radial axis and the 
           ; C axis as the angular axis

The G46 command enables a transformation from an X/Y Cartesian axis plane to a polar coordinate system. G45 command disables the polar coordinate transformation. The G46 command requires the use of the G52 command to define the axes.

The polar coordinate system has a linear positioning device that holds the tool and a rotational device that holds the part centered around its axis of rotation. Use the G1 command, G2 command, and G3 command to program the part in Cartesian coordinates acting on virtual X (horizontal) and virtual Y (vertical) axes, as specified in the G52 command. The controller translates these virtual coordinates to polar coordinates (radius, theta, or angle), which are then used as position commands for two real axes, specified by the G46 command. The controller translates linear and circular motion (for G1 command, G2 command, and G3 command respectively) in the Cartesian space to the correct commands for the rotational (C) and linear (U) axes.

The <LinearAxis> in the G46 command is the radial axis. The <RotaryAxis> is the angular or rotational axes. The first axis that is specified in the G52 command is the horizontal axis and the second axis is the vertical axes. Refer to Figure: Results of a G52 X Y and G46 U C commands for more information.

There are four axes involved in the polar coordinate transformation. As shown in the following table, you can assign an axis to any of the four functions, but the axis that you assign must be a dominant axis for X, Y, and U, and a dependent axis for C. Command motion by using the horizontal and vertical axes (which must be configured as virtual), but the actual motion is generated by the radial and angular axes.

You cannot generate asynchronous motion or jog the axes while this mode is active.

WARNING: Because the G46 command is still active at the end of a program, issue a G45 command at the beginning and end of your programs.

When the G46 command executes, the positions of the X,Y,U, and C axes are critical to the correct operation of the polar coordinate transformation. For example, use X0, Y0, C0, U0 as the coordinates of the four axes at the time that the G46 command executes. The center of rotation of the C axis must always be at X0, Y0. Therefore, you must make sure that the X0 and Y0 coordinates are correct for the mechanics (R = SQRT( X0 * X0 + Y0 * Y0), where R is the physical distance between the center of the C axis and the tool tip). You cannot use the G92 command or fixture offsets to position the X and Y axes because polar coordinates are applied after offsets. You must move (with jog, G0 commands, or G1 commands) the virtual X and virtual Y axes to the correct positions before you activate the G46 command.

When you generate motion in this mode, the speed and acceleration are calculated in the Cartesian XY plane. Velocities and accelerations can exceed user supplied limits, especially for the C axis near its center of rotation. Feedrates of the U and Z axes are not clamped by their DefaultSpeed axis parameters. Instead, speed violations are detected at a lower level and reported as a velocity command trap (instead of a clamp, it is an error). Acceleration violations are trapped as current and position errors.

Verify the state of the polar transformation mode. You can do this by using the TASKSTATUS Status Function to view the RThetaPolarActive Bit 1 of TaskStatus2, or by looking for the G46 command in the Modal Status tab of CNC Operator Interface.

Note: You cannot use cylindrical coordinate transformations (G47 command) in the G46 command mode.

Note: You can use cutter compensation in the G46 command mode.

Note: The virtual Cartesian axes must be virtual and dominant type axes.

Note: The real angular polar axis must be a dependent type axis and the real radial polar axis must be a dominant type axis.

Warning: Do not try to command motion through the origin (Cartesian axes = {0, 0}) because it causes a discontinuous step in the angular coordinate position command.
